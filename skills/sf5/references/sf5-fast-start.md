# SF5 Fast Start

Use this file when the goal is simple and fast: connect SF5, find a known pattern, assemble markup, and validate it without rediscovering the whole ecosystem.

## Fastest Working Route

1. Sync source repositories:

```bash
python3 skills/sf5/scripts/sync_source_repos.py
```

2. If the task sounds like a documented utility/layout question, query docs atlas first:

```bash
python3 skills/sf5/scripts/query_ui_doc_manifest.py \
  --manifest /Users/rim/Documents/GitHub/ai-codex-skill-sf5/skills/sf5/references/ui-doc-manifest.json \
  grid spacing button --limit 12
```

3. If the task sounds like "show me working markup", search `ui-play` examples first:

```bash
rg -n "sf-button|sf-input|<smart|sf-code" source/simai/ui-play/examples
```

4. Assemble the result from the narrowest layer:
  - utilities only for layout and spacing
  - shipped component classes when a static component is enough
  - smart-components only when orchestration/state/template loading is actually needed

5. Validate with strict checks:

```bash
python3 skills/sf5/scripts/validate_sf5_html_files.py --strict --catalog-strict /tmp/example.html
```

## Minimal Runtime Connection

For standalone HTML/testing, the actual runtime pattern seen in `ui` and `ui-play` is:

```html
<script>
  window.sfPath = "/simai/";
  window.sfSmartPath = window.location.origin;
</script>
<link rel="stylesheet" href="/simai/core/css/core.css" />
<script type="module" src="/simai/core/js/core.js"></script>
```

Utility classes are part of the current Simai Framework runtime. Load the
normal current runtime rather than a separate utility-only legacy bundle.

## Choosing Between Utilities, Components, And Smart Components

- Use utilities when the task is mostly layout, spacing, typography, colors, grid, or responsive behavior.
- Use shipped components from `simai/ui` when the task is presentational and the runtime can load a known component.
- Use smart-components only when the feature needs template orchestration, loader-managed initialization, or serialized props/events.

## Smart-Component Practical Notes

- Docs currently describe smart-components primarily through loader docs, not a full dedicated handbook.
- In docs, smart-components are inserted via `<smart ... />`.
- In vendor registries, many smart flows are also keyed by `sf-code`.
- In practice, verify both:
  - docs contract in `ui-doc`
  - real examples in `ui-play/examples/smart-components`
  - runtime existence in `ui-smart/smart`

## When To Escalate Beyond Fast Start
